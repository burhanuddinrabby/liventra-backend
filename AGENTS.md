# AGENTS.md — Liventra Backend

Livestock-farm management REST API: TypeScript + Express 5 + Mongoose 9 + Zod v4 + JWT, single package, ESM (`"type": "module"`). No README. The client is the separate Next.js repo at `../frontend` (see `../frontend/CLAUDE.md`); its `app/lib/api.ts` mirrors this API's response envelope, error shape, and multipart field names, so keep it in mind when changing those.

## Commands (run from this `Backend/` directory)

- **Dev**: `npm run dev` (`tsx watch ./src/server.ts`). Must run from `Backend/`: `dotenv` reads `<cwd>/.env` and multer writes `<cwd>/uploads`.
- **Typecheck**: `npx.cmd tsc --noEmit` (no npm script; verified clean). PowerShell blocks the `npx.ps1` shim on this machine, so use `npx.cmd`.
- **Lint**: `npx.cmd eslint src`. Expect exit 1 from 2 pre-existing `no-unused-vars` errors (`next` in `globalErrorHandler.ts`/`notFound.ts`) plus warnings — don't chase them. `npm run lint:fix` is broken (delegates to a nonexistent `lint` script).
- **Format**: `npm run format`. There is no Prettier config, so defaults (2 spaces, double quotes) rewrite the existing 4-space/single-quote files; avoid repo-wide formatting in feature diffs.
- **Test**: none configured; `npm test` exits 1. Don't invent test commands.
- **Build/prod**: no build script — `npx.cmd tsc`, then `npm run start:prod` (`node ./dist/server.js`).

## Architecture

- `src/server.ts` connects Mongo (`MONGO_URL`), fire-and-forgets `seedSuperAdmin()` and `FarmMemberServices.syncOwnedFarmMemberships()`, then listens on `PORT`. It is not the Express app — `src/app.ts` is.
- `src/app.ts`: `requestContext` (`req.requestId`, `X-Request-Id`) → `cors` with the `CLIENT_ORIGINS` list (`utils/clientOrigins.ts`; missing = `*` outside production, none in production) → `express.json` + cookie-parser, mounts `/api/v1` → `src/app/routes/index.ts`. Keep the catch-all as `app.all('{*splat}', notFound)` — path-to-regexp v8 syntax; `'*'` throws.
- Mounted routes: `/users` (auth/profile/admin), `/farms` (farm CRUD + nested `/:farmId/members` → `farmMemberRouter` and `/:farmId/animals` → `animalRouter`), `/breeds`, `/feed-ingredients` (global master catalog; audited writes via `auditLog/auditLog.utils.ts` `recordAuditLog()`, best-effort, atomic `LOG-000001` counter), `/feed-formulas` (global feeding blueprints: server-calculated nutrition/cost, one active default per exact context via partial unique index, scientific edits on a formula referenced by `feedrecommendations` create a new version record; `/match` ranks formulas for an animal context), `/farms/:farmId/feed-recommendations` (+ `/farms/:farmId/animals/:animalId/feed-recommendations`): immutable per-animal snapshots `REC-YYYY-NNNNNN` (atomic per-year counter) from a rule engine in the service (`RECOMMENDATION_RULE_VERSION`); preview never writes; confirming supersedes the animal's previous Confirmed/Expert Approved plan via `runInTransaction` (falls back to compensation on a standalone mongod); only Drafts can be deleted. `/farms/:farmId/feed-records` (+ `/farms/:farmId/animals/:animalId/feed-records`): actual feeding events; create/correct/void run in `executeAtomically` (transaction, or undo-step compensation on standalone) and move farm stock through `inventory/inventory.utils.ts` `applyStockChange()` + `InventoryTransaction` ledger rows (`referenceType: "FeedRecord"`); corrections/voids move only the ledger difference; records are voided, never deleted. `/farms/:farmId/inventory` + `/farms/:farmId/inventory-transactions`: farm stock items `INV-YYYY-NNNNNN` and their append-only ledger `TRX-YYYY-NNNNNN` (both atomic per-year counters). `currentStock` is never written directly — create with `currentStock > 0` also writes the opening transaction, `PUT` refuses `currentStock` and locks `unit`/`itemType`/`referenceId` once movements exist; `status` is always derived through `deriveInventoryStatus()` (Inactive → Expired → Out of Stock → Low Stock → Available) and list/dashboard/alert endpoints filter on a `derivedStatus` computed in the aggregation (`derivedFieldsStage()`), never on the stored column (`POST /inventory/sync-statuses` is the manual version of the daily `inventory.sync` job). `referenceId` is polymorphic and required for Feed/Medicine/Vaccine (FeedIngredient/Medicine/Vaccine masters), refused for the rest. Movements go through `POST /inventory-transactions` only: per-type role matrix (`TRANSACTION_TYPE_PERMISSIONS`), `Vaccination Usage`/`Treatment Usage` rejected (their own workflows write them), quantity always positive with direction from `TRANSACTION_DIRECTIONS` (`Return` = inflow, matching what FeedRecord/Treatment/Vaccination already write; `Adjustment` needs an explicit `direction` or a `physicalCount`), unit must equal the item's unit, `Purchase` needs `unitPrice` and re-derives `averagePurchasePrice` by weighted average, all inside `executeAtomically` + the conditional `applyStockChange()` pipeline. Ledger rows are immutable: `DELETE` is always 403 and `POST /inventory-transactions/:id/reverse` writes an offsetting Adjustment/Return that points back at the original (`referenceType: "Manual"`, `referenceId: original._id`) — which is also the double-reversal guard. Low-stock/out-of-stock alerts are returned in the response (threshold *crossing* only), and stored as notifications. Item `DELETE` archives as Inactive; `?hard=true` only with no stock and no ledger history. `/farms/:farmId/milk-records` (+ `/farms/:farmId/animals/:animalId/milk-records`): per-session milk production; one active record per animal/day/session (partial unique index), `quantityInLiters` server-normalized, `withdrawalFlag` from a medicine-withdrawal check that reads the not-yet-built `treatments`/`medicines` collections raw (`milkRecord.utils.ts`); DELETE voids by default, `mode: "hard"` only for duplicates; spoiled milk → `PATCH /:id/quality` `Rejected`. `/farms/:farmId/weight-records` (+ `/farms/:farmId/animals/:animalId/weight-records`): body-weight history; `weightInKg` server-normalized, ADG re-derived for the whole animal timeline after every write, `Animal.currentWeight` mirrors the latest valid measurement (backdated rows never overwrite it), DELETE voids by default (`mode: "hard"` for duplicates), growth-summary compares observed ADG with `FeedRecommendation.inputSnapshot.targetADG` and lists animals overdue for weighing. `/vaccines`: global vaccine master catalog (same shape as feed-ingredients: admin writes, audited, retire-not-delete, `?hard=true` only when unreferenced); `targetDiseaseIds` and usage counts read the `diseases`/`vaccinations` collections raw; `/farms/:farmId/vaccinations` (+ `/farms/:farmId/animals/:animalId/vaccinations`): per-animal dose events `VACLOG-YYYY-NNNNNN` (atomic per-year counter), `Scheduled → Completed | Missed | Cancelled`; overdue is derived, never stored; `nextDueDate` is stage-aware (`computeNextDue()` in `vaccination.utils.ts`: first dose → booster, later → repeat); completing deducts vaccine stock (`itemType: "Vaccine"`, FEFO) with a `Vaccination Usage` ledger row in `executeAtomically`; `Completed → Cancelled` is an Owner/Manager reversal that returns stock; only unexecuted Scheduled/Cancelled drafts can be deleted. `/diseases`: global disease master catalog (admin writes, any signed-in user reads; inactive rows listed for admins only but readable by id/code for all); normalized duplicate-name check (`&`=`and`, punctuation-insensitive → 409; initials/missing "Disease" → 409 unless `confirmDuplicate: true`); `recommendedVaccineIds` ↔ `Vaccine.targetDiseaseIds` kept in sync inside `executeAtomically` (opt out with `syncVaccineTargets: false`); `/search-by-symptoms` is a reference ranking that always returns a not-a-diagnosis disclaimer; DELETE soft-deactivates, `?hard=true` deletes only when no `treatments`/`vaccines` reference it (otherwise deactivates). `/medicines`: global medicine master catalog (admin writes, audited; inactive rows listed for admins only, readable by id/code for all); `dosageForm` ↔ `administrationRoute` compatibility matrix in `medicine.constants.ts` (served by `/meta`); normalized duplicate check (name+strength+form+manufacturer, or generic+brand+manufacturer+strength+form → 409); identity fields (generic/brand/manufacturer/strength/form) locked once `treatments`/`inventories` reference it (raw collections); DELETE retires, `?hard=true` only when unreferenced (otherwise 409). `/farms/:farmId/treatments` (+ `/farms/:farmId/animals/:animalId/treatments`): clinical episodes `TRT-YYYY-NNNNNN` (atomic per-year counter), always created `Ongoing`; `Ongoing → Recovered | Referred | Cancelled`, reopen (→ Ongoing) is Owner/Manager only; every write re-derives `Animal.healthStatus` across all of the animal's episodes (`syncAnimalHealth`, Quarantine never overwritten); medicine lines validated against the Medicine route/form matrix + `DOSAGE_UNIT_COMPATIBILITY`; prescription-only medicines need an Owner/Manager/Vet as caller or `treatedBy`; stock moves only via `POST /:id/consume-inventory` (`Treatment Usage` ledger, FEFO, `executeAtomically`), cancelling an episode that drew stock needs `restoreStock`; withdrawal is derived (`computeWithdrawals()` in `treatment.utils.ts`, max end across lines); DELETE only for Ongoing/Cancelled episodes with no stock movement. `/farms/:farmId/breedings` (+ `/farms/:farmId/animals/:animalId/breedings`): heat / service events `BRD-YYYY-NNNNNN` (atomic per-year counter), always created `Pending` and never auto-failed (overdue is derived); female + Active + ≥12 months + not Calf/Pregnant + no active Pregnancy; AI needs `semenBatchNo`, Natural Mating needs an Active male `bullId` and no semen batch; `PATCH /:id/pregnancy-result` Confirmed creates the `pregnancies` row (`PRG-YYYY-NNNNNN`, unique `breedingId`) + sets `Animal.reproductiveStatus = Pregnant` only for the animal's latest breeding, all in `executeAtomically`; corrections (Failed → Confirmed/Pending, Confirmed → Failed closing the Pregnancy as Failed) need a reason; DELETE (Owner, reason) only without a linked Pregnancy. `/farms/:farmId/pregnancies` (+ `/farms/:farmId/animals/:animalId/pregnancies`): gestation episodes `PRG-YYYY-NNNNNN` (atomic per-year counter), created only from a `Confirmed` breeding with a unique `breedingId` (1 Breeding → 1 Pregnancy) on a Female + Active animal with no open `Pregnant` episode; `conceptionDate` defaults to the service date (heat → service + 3 days), `expectedCalvingDate` is frozen at conception + `CATTLE_GESTATION_DAYS` (240–320 allowed); `Pregnant → Delivered | Aborted | Failed` only (`PREGNANCY_STATUS_TRANSITIONS`), via `PATCH /:id/deliver` (calfCount 1–10, `Twin` only at 2, mother → `Lactating`) and `PATCH /:id/outcome` (reason required, mother → `Open`); every write re-derives the mother's `reproductiveStatus` from her *latest* episode (`syncMotherReproductiveStatus`), all in `executeAtomically`; overdue / upcoming calving, gestation duration and expected-vs-actual variance are derived, never stored; `GET /eligible-breedings` is the create-form picker (Confirmed breedings with no pregnancy yet) and `GET /:id/audit-logs` is the change history (pregnancy + upstream breeding rows); PUT corrects only `conceptionDate` / `expectedCalvingDate` / `remarks` (reason required for dates) and DELETE is **always 403** — pregnancy records are historical and are closed with an outcome instead.
- Shared foundation (`api_documentation/realtime.md`): `realtime/realtime.ts` (Socket.IO; emit helpers never throw, call them after commit), `jobs/` (`scheduler.ts` job list, `runJob` Mongo lock, minute-or-coarser schedules, jobs must catch their own errors because an unhandled rejection exits the process), `utils/farmAccess.ts` (`resolveFarm` / `requireRole` / `requireWritableFarm`, for new modules only; same rules as `resolveFarmAccess`). Any new code that changes a membership or disables an account must call `removeUserFromFarm` / `disconnectUser`.
- `notification` (`api_documentation/notification.md`): `NotificationProducers.*Changed()` re-read a saved record and reconcile its rows; call them after commit (they never throw). The hourly job runs the same code per farm. Event titles are the duplicate key and the frontend translation key: never rename a used one.
- `device` (`api_documentation/device.md`): hardware registry `DEV-000001`. Connection and health are separate; only `recordDeviceSync()` sets Online. `device.links.ts` is the single place that touches the not-yet-built `deviceassignments` / `sensordatas` collections (plans 6 and 7 replace it).
- Modules live in `src/app/modules/<name>/`: `*.route.ts`, `.controller.ts`, `.services.ts`, `.model.ts`, `.validation(s).ts`, `.interface.ts`, `.constants.ts`, `.utils.ts`; each exports an object (`userRouter`, `UserController`, `UserServices`, `farmValidations`).
- `breed` is the newest and cleanest reference: service-layer field whitelisting/coercion, generated immutable `breedCode`, deactivate by default (hard delete only when unreferenced). `farm` remains the reference for farm-scoped RBAC; its unimplemented routes are commented out inline in route/controller/services — uncomment and implement rather than rewriting.
- `src/app/builder/QueryBuilder.ts` drives list endpoints: `.search([...]).filter().sort().paginate().fields()`, then `await Promise.all([query.countTotal(), query.modelQuery])`. `search()` interpolates `searchTerm` straight into `$regex` — escape user input first (see `escapeRegex` in `breed.utils.ts`).

## IDs, auth and farm RBAC

- Generated display IDs: users `U-YY-NNNN`, farms `FARM-NNNNN`, breeds `BREED-00001`, feed ingredients `ING-00001`, feed formulas `FF-000001`, vaccines `VAC-00001`, diseases `DIS-00001`, medicines `MED-00001`. Inventory items (`INV-YYYY-NNNNNN`) and stock transactions (`TRX-YYYY-NNNNNN`) instead use the atomic `InventoryCounterModel` per-year counters. All are last-row+1 and non-atomic; the unique index is the real guard, so retry on duplicate key 11000.
- JWTs carry `{ userId, role }` where `userId` is the custom string. `Farm.ownerId` and `FarmMember.userId` are ObjectIds — services look the user up (`UserModel.findOne({ userId })`) and use `_id`.
- `auth(...roles)` verifies the token, then loads the user and rejects inactive accounts; role checks use the DB `systemRole`, not the token. `auth()` with no roles allows any logged-in user. It does not check `isDeleted`; `/users/login` refuses inactive/deleted accounts after the password check.
- Farm-scoped authorization is service-layer: `resolveFarmAccess` in `farmMember.service.ts` requires an active `FarmMember` row. Only platform `superAdmin` and the farm's `Farm.ownerId` account bypass it (treated as `Owner`); platform `admin` does **not** bypass. Owner/Manager manage members; only Owner (or superAdmin/owner account) deletes.
- `FarmMember`: one *active* membership per `(farmId, userId)` via partial unique index; inactive rows are history. `nid`/`salary` are `select: false` and management-only. `Farm.ownerId` must always have an active `Owner` row — created on farm creation, backfilled at startup (`syncOwnedFarmMemberships`), and re-synced on ownership transfer (old owner → `Manager`).
- `SystemRoles` = `user` / `admin` / `superAdmin` (`auth.constants.ts`). `TSystemRole` is `keyof typeof SystemRoles` (uppercase keys), so don't use it for stored values.

## Conventions

- Relative imports end in `.js`; type-only imports use `import type` (`verbatimModuleSyntax`). tsconfig is strict with `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`, `include: ["src"]`.
- Handlers: `catchAsync` + `sendResponse(res, { statusCode, success, message, data, meta? })`; throw `new AppError(status.X, 'msg')`; status codes from `http-status`.
- `globalErrorHandler` maps ZodError, Mongoose `ValidationError`/`CastError`, duplicate key `11000`, `TokenExpiredError`, `AppError`; response is `{ success, message, errorSources, err, stack }` (stack only when `NODE_ENV=development`).
- Zod is **v4**: use top-level `z.email()`, not `z.string().email()`.
- `validateRequest(schema)` validates only `{ body, cookies }` and **discards** the parsed result: coercions/defaults/transforms never reach handlers and unknown keys aren't stripped. Whitelist/coerce in the service (breed pattern) or filter manually. It never validates params or query, so services must parse those themselves (`QueryBuilder` receives raw strings).
- Multipart field names differ by module: users `file`, farms `logo`, breeds `image`, animals `profilePhoto` + `gallery`, finance receipts `attachment`. User/farm creation put the JSON body in `data` and parse it inline (`JSON.parse(req.body.data)`, no guard).
- Uploads: multer writes to `<cwd>/uploads` (not git-ignored, except `uploads/finance`: private receipts kept on disk and streamed by the finance routes), `uploadImageToCloudinary(name, path)` uploads then deletes the local file.

## Gotchas

- `userSchema.pre('save')` re-hashes `password` on **every** save. Use `findOneAndUpdate`/`updateOne` for user updates; only call `.save()` when intentionally assigning a new plain password (change-password and reset-password rely on this).
- Soft delete is only a convention: the `isDeleted` filter hook in `auth.model.ts` is commented out, and `DELETE /users/:id` just sets `isActive: false, isDeleted: true`. Services filter `isDeleted` explicitly. If you re-enable such a hook, use `this.where()` — `this.find()` mutates `query.op` and breaks post-hook dispatch.
- Farm creation requires an active, `emailVerified` user, rejects a second `Setup` farm, and rejects duplicate `farmName` per owner. If the Owner-membership insert fails, the new farm is deleted (compensating workflow).
- `InventoryTransaction.direction` (`In`/`Out`) is the one field added beyond the final schema: the schema has no `transactionDirection`, so `Adjustment`/`Return` rows would otherwise have an unrecoverable direction. It is optional and only written by the inventory module — always read it through `resolveDirection()`/`signedDelta()` in `inventory.utils.ts`, which falls back to the type map for the rows FeedRecord/Treatment/Vaccination write.
- Expense + Income (`/farms/:farmId/expenses`, `/incomes`, `/finance/profit-loss`) share one life cycle in `finance/finance.ledger.ts` (Pending → Paid/Received → or Cancelled, never deleted; Owner/Manager/Accountant only). `POST /expenses/purchase` runs inside the inventory write through its after-transaction hook, so stock and expense commit together. The schema has no payment-date / cancel-reason fields: those are bracketed trail lines inside `description`, split out again as `notes`.
- Enum values are display strings stored as-is: `FarmStatuses.ARCHIVED === "Suspended"`; farm roles are `Owner/Manager/Worker/Veterinarian/Accountant`; breeds are deactivated via `PATCH /breeds/:id/status` (or `DELETE /breeds/:id`); `DELETE ?hard=true` removes one only when no animal/feed formula references it. Farms: `DELETE /farms/:farmId?mode=suspend|permanent` (owner account or admin/superAdmin); permanent only for a `Suspended` farm and cascades through every farm-scoped collection (`FARM_DATA_SOURCES` in `farm.services.ts` — add new farm-scoped models there).
- Breed names are unique case-insensitively (`collation: { locale: "en", strength: 2 }`) by both index and pre-check; `breedCode` is immutable. Breed route order matters: `/lookup`, `/meta`, `/stats`, `/code/:breedCode` must stay above `/:id`.
- User creation returns **200**, not 201. Profile updates use dotted paths (`address.upazila`) so the address subdocument is not clobbered.
- Email OTPs: 6 digits, 2-minute TTL, only a sha256 hash stored, 5 wrong attempts burn the code. The TTL index uses `{ expireAfterSeconds: 0 }`; mongoose's `{ expires: 0 }` is falsy-skipped and creates a plain index. Registration does **not** send an OTP — the client must call `POST /users/verify-email` without `otp` to request one.
- `.env` is loaded from `<cwd>/.env`. Required: `MONGO_URL`; `SUPER_ADMIN_PASS` (`src/app/DB/index.ts` throws at import and seeds `U-00-0000`); `BCRYPT_SALT` (missing → `Number(undefined)` → bcrypt throws on every save); `JWT_SECRET`/`JWT_SECRET_EXP`/`JWT_REFRESH_SECRET`/`JWT_REFRESH_SECRET_EXP`; `SMTP_USER`/`SMTP_PASS` + `RESET_UI_LINK` for email; `CLOUDINARY_NAME`/`CLOUDINARY_KEY`/`CLOUDINARY_SECRET` for images. Optional: `CLIENT_ORIGINS`, `APP_TIMEZONE`, `JOBS_ENABLED`, `TRUST_PROXY`. `NODE_ENV` controls cookie `secure` and stack traces.
- Never commit `.env` (DB URI, JWT secrets, SMTP + Cloudinary creds). Git-ignored: `.env`, `.opencode`, `node_modules`, `dist`, `uploads/finance`.
